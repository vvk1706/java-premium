Java Modernization Analysis Report

Project: Driver License Issuance System (DLIS) • Target Platform: WAS Liberty / zLinux

Executive Summary

An in-depth analysis of the Driver License Issuance System (DLIS) codebase has been completed. DLIS is a high-performance enterprise Java EE application deployed on IBM WebSphere Application Server (WAS) Liberty running on IBM zLinux (s390x). The application relies on IBM DB2 JCC XA DataSources for transactional security and is fully integrated with CICS Transaction Server through native JCICS Program and COMMAREA adapters.

Currently, the application runs on Java 11 and is based on the Jakarta EE 8 / Java EE 8 Web Profile specification. While stable and highly modular, the codebase can be significantly improved by modernizing its compiler targets, updating package namespaces, and adopting cloud-native design architectures.

Suggested Modernization Paths

We have formulated three distinct modernization strategies designed to support your security, platform, and code quality requirements:

1. In-Place Liberty Modernization Recommended

Goal: Maintain the WebSphere Liberty container on zLinux but upgrade compiler and runtime standards.

  • Java Upgrade (Java 11 ➔ Java 17/21): Enables modern language features like Records (cleaner COMMAREAs/DTOs) and Text Blocks (highly readable SQL).
  • Namespace Migration (Jakarta EE 8 ➔ 10): Use OpenRewrite to rewrite javax.* imports into jakarta.*, ensuring long-term compatibility with newer Liberty versions.

Recipes: UpgradeToJava17, UpgradeToJava21, JavaxMigrationToJakarta, JakartaEE10

2. Quarkus Cloud-Native Port Cloud Path

Goal: Transition away from JEE Application Servers to container-native microservices for Kubernetes / OpenShift.

  • Migrate stateless EJBs and JAX-RS resources directly into Quarkus using standard Quarkus CDI and reactive components.
  • Sub-second startup speeds, drastically reduced memory usage, and simplified configuration models tailored for Kubernetes.

Workflows: migrate-spring-to-quarkus (leveraging JEE compatibility extensions).

3. Test Coverage Modernization Essential

Goal: Seal off the codebase from regressions before making structural refactoring modifications.

  • Address unit test gaps documented in UNITTEST.md by adding robust test suites for EJBs, JDBC DAOs, and COMMAREA adapters.
  • Use JUnit 5, Mockito, and JaCoCo coverage metrics without requiring live IBM DB2 or CICS regions.

Workflows: java_unit_test_workflow combined with the write-unit-test specialized skill.

Recommended Next Steps

  1. Perform the Java Version Upgrade: Upgrade compiler and source/target configurations to Java 17 or Java 21 to lay the foundation for subsequent refactoring steps.
  2. Execute the Jakarta EE Namespace Migration: Automatically shift imports to jakarta.* to eliminate old JEE dependencies and align the codebase with modern JEE runtimes.
