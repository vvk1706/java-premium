Steps performed

1. Gather unit test info→ 2. Add JaCoCo→ 3. Create test strategy→ 4. Generate tests (10 batches)→ 5. Run all tests→ 6. Visual summary
  1. Gathered information about unit tests in the project. No code coverage tool was found.
  2. Installed JaCoCo. Project facts: Maven build, Java source version 11, 4 modules. JaCoCo 0.8.15 was chosen (Java 11 requires at least 0.8.3).
    • Root pom.xml: added the jacoco.version property and configured jacoco-maven-plugin in pluginManagement with prepare-agent and report goals bound to the default lifecycle.
    • Plugin reference added to each child module that has tests (dlis-core, dlis-cics-bridge, dlis-web).
    • dlis-ear/pom.xml: added the report-aggregate goal. The EAR module already depends on the other modules, so it produces the cross-module aggregate report.
    • Verified the installation by running the unit tests with coverage.
  3. Created the unit test strategy (UNITTEST.md). Selected tasks: Generate Unit Tests, Run Code Coverage; candidate selection strategy: All classes.
  4. Generated tests in 10 batches (one subtask per package group, see below). Each subtask followed the strategy, ran the tests and fixed failures.
  5. Ran all unit tests of the project and previewed the results.
  6. Created this visual summary.

Build and configuration changes made along the way

  • JaCoCo 0.8.15 plugin configuration added to the root, module and EAR pom.xml files.
  • Root pom.xml: removed a duplicate org.mockito:mockito-junit-jupiter entry in dependencyManagement that prevented Maven from reading the project.
  • dlis-core/pom.xml: added mockito-junit-jupiter, and -Dnet.bytebuddy.experimental=true in the Surefire argLine because the test JVM is newer than the Byte Buddy version bundled with Mockito 5.5.0 officially supports.
  • Maven was installed with Homebrew for running the tests.
